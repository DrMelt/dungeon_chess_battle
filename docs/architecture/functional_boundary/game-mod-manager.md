# DungeonChessBattle.Game.Mod.Manager

Godot 端 mod 子系统：mod 包管理、展示装配全过程、展示注册器与包内资源加载、统一获取入口。只被 Game 引用，服务端程序集不携带。与数据面 Battle.Mod.Manager 的分工：数据面管包在磁盘上的形态与两端一致性，本库管展示装配与用户管理。

## 职责

- mod 管理：扫描 mods 根目录，产出 mod 列表（启用态、是否含数据/展示代码、逐项错误、内容指纹），读写启用集。
- 展示装配全过程：建注册表、逐 mod 装载展示代码、执行入口注册、把 mod 声明落地成资源；宿主侧步骤以委托交入，次序由本库执行。
- 展示注册器：写面与读面，同键条目字段级合并。
- 装配写面：一个 mod 一个实例，按归属记录声明与错误，校验展示引用的内容键存在。
- 资源加载：按寻址键读包内图片、场景与展示数据，带缓存，拒绝越出 mods 目录的寻址。
- 资源获取入口：技能/Buff/副本/单位/纹理/场景六类查询、启停与装配期指纹。

## 边界外

- 不持有主工程的 `res://` 路径与脚本类：引擎侧条目与资源留在 Godot 主工程，mod 侧资源随展示工程打包，本库只经挂载后的 `res://mods/{id}/` 前缀加载；装配中的宿主步骤以三个委托交入。
- 不做内容注册与门控：清单解析、路径裁决、依赖排序、指纹与启用集落盘在 Battle.Mod.Manager；内容注册与 BuffTypeId 段校验在 GameConfig。本库只经只读视图校验展示键。
- 不定义包布局：文件名与默认目录来自数据面包管理，产物位置由清单声明并已被定位，本库只消费现成路径。
- 不做行为注册：mod 数据入口直接对接 GameConfig 行为目录，本库不中转。
