# DungeonChessBattle.Game.Mod.Manager

Godot 端 mod 子系统：mod 包管理、展示装配全过程、展示注册表与统一获取入口。只被 Game 引用，服务端程序集不携带。与数据面 Battle.Mod.Manager 的分工：数据面管包形态与内容装配，本库管展示装配与用户管理。

## 职责

- mod 管理：扫描 mods 根目录，产出 mod 列表（启用态、是否含数据/展示代码、逐项错误、内容指纹），读写启用集。
- 展示装配全过程：建注册表、逐 mod 装载展示代码、执行入口注册、把 mod 声明落地成资源；宿主侧步骤以委托交入，次序由本库执行。
- 展示注册表：条目展示数据的读写面，条目同键后注册字段级合并。
- 装配写面：一个 mod 一个实例，按归属记录声明与错误，校验展示引用的内容键存在。
- 条目取数入口：一次装配产出的实例，提供技能/Buff/副本/单位四类条目查询与装配期指纹；启停与重扫等管理动作经它持有的 `ModCatalog`。

## 边界外

- 不持有主工程的 `res://` 路径与脚本类：mod 侧资源随展示工程打包，本库只把清单声明的包挂载进资源系统，包内资源由 mod 侧按 `res://mods/{id}/` 前缀自行加载；装配中的宿主步骤以两个委托交入。
- 不做内容注册与门控：清单解析、路径裁决、依赖排序、指纹、启用集落盘与内容注册都在 Battle.Mod.Manager 的数据面装配。本库只经只读视图校验展示键。
- 不定义包布局：文件名与默认目录来自数据面包管理，产物位置由清单声明并已被定位，本库只消费现成路径。
- 不做行为注册：mod 数据入口经 Battle.Mod.Manager 的引导上下文写入 GameConfig 行为目录，本库不中转。
- 不持有全局实例：禁止以静态成员在本库持有装配结果或任何可变状态，装配产物一律以实例交回宿主，由 Game 侧 ServiceLocator 持有。
